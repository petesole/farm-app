DAILY FIELD D-NOTE REGISTER — 11/11/2026

Agreed behaviour
Daily DNotes has Add DNotes with one date (defaults to yesterday) and multiple
start/end lines for changing books during the day. Successful, backend-confirmed
save closes the entry screen and refreshes the table on that date. Missing WB
slips have red rows. Missing / Not missing is an explicit two-position filter.
All existing WB columns, net weights, field allocations, sorting, print and CSV
are retained. Historical WB-only rows remain visible under Not missing, so
registering expected notes does not hide previous report records.

Matching
Full book/note identifiers are text, never dates. 02/046 matches 2/46. A delayed
WB arrival matches the original expected D-Note date. Multiple WB slips for one
D-Note show a warning; multiple field allocations count the truck weight once.
Missing rows remain visible under season/field filters because their field and
season cannot be known until a WB record arrives. Auto-refresh is every 30 seconds,
on browser visibility, manually, and immediately after a successful save.

Validation / permissions
Each line stays inside one book. End must be >= start. Overlaps in one save or
against a previous day are rejected atomically; no partial ranges are saved.
The same request UUID is used to retry uncertain saves. A committed save is
verified before closing, including when a network timeout hid its response.
Only the existing server-verified WB Admin role can read or add this register.
There is no change to WB computer software, tickets, allocations or stock.
No test D-Notes were left in the live database. No historical ranges are inferred.
