JSPL Sprayer Android app — agreed workflow, 13/11/2026

User decisions: Android; every spray in the existing Stock spray-planning scope; physical completion only after the full spray has been issued. Stock currently plans/issues sprays under JS/HS ownership, retaining its existing AO-to-HS stock transfer rule. No stock rule is changed.

Home lists active-trace sprays without a sprayer completion date, including stock-issued jobs that Stock already regards as completed. Missing or partial stock issue is labelled Awaiting stock. Both awaiting-stock and issued jobs open an offline tank mix, using the same full/part tank calculation as the existing application sheet. Tank capacity can be confirmed locally; changing it does not edit the Stock plan.

After full issue, the sprayer can enter an actual completion date. Saving offline persists the completion in SQLite, removes it from the phone dashboard and shows it in dated history as Awaiting sync. History contains Date, Trace, Input Name and Rate/Ha only, with reciprocal searchable filters. Total used is omitted. Only trace codes with no end/closing date are downloaded. Closing a trace sends removal records at next sync, covering its plans and history.

Physical dates are held in separate sprayer_completion records. Saving or correcting a sprayed date never posts stock, changes Stock job status or edits prior movements. Admin can review completion history, change a date or reopen a completion with a required explanation and version check. Stock cards may display the separate sprayed date beside their unchanged Stock status.

Phone access is a dedicated active Sprayer role, assigned through Stock Staff Access. It grants no Stock, Fuel, Labour or Main access. Admin can review the phone and correct history. The offline identity is stored in Android SecureStore only after server-verified sign-in. Cached records and completion queues are isolated by user ID. A cached UI role is never used to authorize server operations. Online opening/sync verifies current server access; revocation clears the offline admission receipt at next contact while retaining account-scoped pending data.

Sync is manual, available on every phone screen, with connection type, last successful sync time and pending/review counts. First/full downloads default to Wi-Fi; the user can explicitly allow mobile data. Subsequent mobile and Wi-Fi syncs send queued dates and only changed spray records, never the full Stock catalogue, balances, photos or unrelated farm data. Ingredients and local calculations are usable without reception. App-package updates are installed separately; automatic over-the-air package downloads are disabled for this APK variant.

A private dirty-job projection and cursor/epoch feed capture changes to plans, ingredients, issues/returns, physical dates, trace closure, item names/units and tank settings. Recipe hashes reject stale offline completion rather than overwriting a changed plan. Full issue and dates are rechecked server-side. Future dates and completion before the final stock issue are rejected. Stock operations and physical completion use the same inventory lock for the eligibility check, without posting a stock document.

Queued operations have persistent UUIDs. Duplicate/lost responses return the prior receipt, and uncertain saves cannot be edited/discarded until verified. Rejected changes retain their entered date for review. Connection loss after server commit is treated as unconfirmed. Weak sign-in connectivity does not clear valid offline access. Downloads persist cursor progress per page; interrupted full refreshes keep previously cached records until the snapshot finishes. Last successful sync is advanced only after the whole cycle completes.

The sprayer APK uses package com.jspl.sprayer and installs separately from the existing Farm app. The normal Farm app name/package and existing build profiles are preserved. The new sprayer-apk internal build profile targets the current development Stock V2 backend. No Play Store publication or production channel promotion is requested.
